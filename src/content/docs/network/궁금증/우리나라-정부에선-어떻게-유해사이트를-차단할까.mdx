## DNS 차단

- DNS 서버에 Query를 하는 중에 ISP 업체에서 제공하는 DNS 서버에 상대 호스트 도메인 네임에 대한 IP 주소를 묻는 요청이 오면 IP 주소를 가르쳐주는 대신 차단 사이트의 IP 주소를 알려주는 방식.
- 이러한 차단은 ISP 업체(KT, SKT, LG U+)에서 차단하고 있음.
- 이러한 차단은 해외 DNS 서버를 사용하면 우회할 수 있음. VPN 사용도 똑같음.

### HTTP 통신 헤더의 호스트 정보를 이용한 차단 방식

- DNS Query 및 상대 서버와 세션을 맺고난 이후 클라이언트가 서버에게 HTTP 통신을 요청함.
- HTTP 통신 요청 시 HTTP Header 값에 목적지 도메인 네임이 포함되어 있음. 이런 값을 확인 후 차단함.
    - 이러한 차단 또한 ISP 업체에서 차단함.
- SSL 인증서를 사용하는 HTTPS 통신을 이용하면 HTTP 통신까지 전 구간이 암호화가 되기 때문에 ISP 업체는 정보를 확인하지 못하고 차단을 시킬 수 없음.
    - 차단은 가능할 수도 있으나 확인하기 위해 들어가는 시간과 비용이 너무 크기 때문에 수행하지 않음.

### SNI(Server Name Indication) 차단방식

- HTTP/HTTPS 통신하기 전 TCP 3-way handshake 과정에서 Entension : Server_name 필드에 호스트 이름(사이트 이름)이 표시될 수 있음.
- ISP 업체에서 이 정보를 이용하여 차단함. DNS Query와 HTTP 통신 구간만 암호화가 되기 때문에 ESNI(Encrypted SNI)을 이용하면 우회가 가능함.
    - 현재 Firefox Version 63 이상을 설치하여 ESNI 옵션을 켜는 방법을 사용하여 SNI 차단을 우회할 수 있음.

#### SNI(Server Name Indication)이란?

- "한 개의 공인 IP 주소로 여러 개의 웹사이트를 안전하게 호스팅할 수 있을까?"라는 물음에서 시작됨.
    - 예전에는 웹 서버 상에 공인 IP 주소가 하나로 지정되어, 1대 1로 공인 IP를 사용하고 있었음.
- SNI는 TLS 핸드셰이크의 클라이언트 Hello 메시지 안에 도메인 이름을 포함시키는 확장임.
    - 즉, 서버는 TCP 연결 이후 TLS 핸드셰이크 초기에 "클라이언트가 요청하는 도메인"을 파악할 수 있음. 해당 도메인에 맞는 인증서를 제공할 수 있게 됨.
- 이를 통해서 하나의 공인 IP 주소로도 여러 HTTPS 사이트를 운영할 수 있게 됨.

## Cloudflare 레벨 지역 차단

- 최근 정부에서는 정보통신망 이용촉진 및 정보보호 등에 관한 법률 개정안에 따라, Cloudflare에서 유해 사이트를 운영하고 있는 경우, 유해 사이트를 차단하기 시작하였음.
- 차단된 사이트에 접근하는 경우, HTTP 451 오류 페이지를 표시함.
    - 이 경우 사이트 운영자가 국내에 서버를 두지 않는 CDN을 사용하거나 사용자가 네트워크 경로 자체를 우회하는 고적인 VPN, Tor 프록시를 사용하지 않은 한 우회할 수 없음.
- [Government-ordered blocking under Korea Network Act](https://lumendatabase.org/notices/73101162)를 참고하면 실제로 대한민국 방송미디어통신위원회에서 Cloudflare 측에 Cloudflare를 사용하고 있는 불법 사이트에 대하여 차단을 요청한 내용임.
